## Defects discovered and fixed during RC exercise

1. **Host validation test transport:** Node fetch did not deliver the overridden Host header as intended. Raw node:http test now verifies actual request bytes and 403 rejection; server guard was not relaxed.
2. **Checkbox pending-state interaction:** immediate rollback made successful UI checks unreliable. Pending checkbox state now remains until save completes, with rollback on failure. Desktop/mobile success and failure scenarios pass.
3. **Distribution link closure:** root catalog referenced a local-only research report. Validator now rejects linked files omitted from manifest; fixture copies validated current manifest while independently enforcing essential files. Added regression and included linked documents.
4. **Evidence quality:** existing comparison document retained with prominent historical/unverified warning. Its unsupported feature/cost/absence claims are not used as RC evidence.

## Reproduce

From repository or extracted source root:

```powershell
python scripts/validate.py
python -m unittest discover -s tests -p 'test_*.py' -v
Set-Location example/full-stack-todo-express-vanillajs
npm.cmd ci --ignore-scripts --no-fund
npm.cmd run check
npm.cmd run test:api
npx.cmd playwright install chromium
npm.cmd run test:e2e
npm.cmd audit
npm.cmd start
```

Stop on nonzero exits. Open `http://127.0.0.1:3000`; Ctrl+C stops server. `npm start` is manual run, not a command that terminates during CI. Detailed architecture, API, recovery and configuration: [example guide](../../example/full-stack-todo-express-vanillajs/GUIDE.md).

[Machine-readable gate results and tested file hashes](evidence-20260909/gates.json) preserve candidate evidence. Candidate contained an in-progress report; final release differs only in finalized report/evidence/manifest. Finalizer must compare every executable and lockfile hash against tested state and rerun core checks after documentation changes. Final ZIP SHA-256 is recorded in a separate delivery sidecar to avoid a self-referential archive hash.

## Release boundaries and remaining work

- Local-demo RC scope: eligible for human review after final archive closure/integrity check. No release version assigned; package.json remains private `0.0.0`, not an asserted release tag.
- Server binds loopback. No auth or remote deployment allowed by this design; local processes/users can access it. Host/origin/CSP controls are not authentication.
- One process/store instance owns one JSON file. No multiple-writer locking, database-grade transactions, large-data scaling guarantee, directory-fsync/power-loss certification, or production backup/restore drill.
- Verified onboarding here means clean package commands run. It does not prove another developer independently understood an interrupted task, every agent follows instructions, or all real projects can ship safely.
- Audit is a time-specific advisory check, not proof of security. Local paths/tool locations in logs are provenance, not credentials; never add actual secrets/data to this package.
- Build pipeline absent by design: vanilla assets served directly. Syntax/API/browser/core checks are applicable gates; no fabricated frontend build result.
- No public publish, commit, tag, installed-client compatibility test, CI-provider run, cross-OS validation, comparative benchmark, or claim of zero bugs/token savings.
